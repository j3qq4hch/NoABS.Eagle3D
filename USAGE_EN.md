# NoABS Eagle3D — Usage Guide

## release_artifacts structure

```
release_artifacts/
  tools/
    export3D.ulp          ← Eagle ULP script (step 1)
    export3D_step2.ulp    ← Eagle ULP script (step 2, launched automatically)
    eagle2gltf/           ← GLB board model generator
    eagle2step/           ← STEP board model generator
  glue/                   ← GUI tool for attaching 3D metadata to footprints
  drawexe_bundle/         ← OCCT engine (used by eagle2step)
```

---

## ULP scripts (export from Eagle)

The ULP scripts automate the entire 3D export process from within Eagle.

### Quick start

1. Open your board in Eagle Board Editor
2. **File → Execute Script** → select `export3D.ulp`
3. On the first run a settings dialog will appear:
   - **DPI** — texture resolution (400 is a good balance, 600+ for highly detailed boards)
   - **Tools dir** — the `tools/` folder from `release_artifacts` (where the `.exe` files are)
   - **GLB dir** — folder with component GLB models (can be left empty — board only, no components)
4. Click OK. Eagle exports the texture layers, then automatically launches `export3D_step2.ulp`, which calls `eagle2gltf.exe`
5. The resulting `.glb` file appears next to the `.brd` file

**On subsequent runs the dialog does not appear** — settings are saved to `NoABS_tmp/export3d_settings.ini` next to the BRD file.  
To change settings, delete that file and run the ULP again.

### Component GLB files

The 3D component model library in GLB format comes from a separate repository.  
Set the folder path in the **GLB dir** field. File names must match Eagle footprint names (case-insensitive).

## Component placement metadata

For a component's 3D model to be placed correctly on the board (correct height, rotation, and offset from the footprint origin), the footprint description must contain metadata in the `<!--3d:{...}-->` format.

This metadata holds transformation parameters: X/Y/Z offsets and rotation angles. Without it, the component will be placed at the footprint origin with no adjustments, which will result in incorrect positioning for most packages.

The metadata is embedded into the Eagle library using **glue** — the GUI tool included in this package. Glue lets you visually adjust the 3D model placement parameters and save them to the footprint description.

## eagle2gltf — GLB board model generator

Generates a `.glb` file with the 3D board model and optionally the components.  
GLB files can be opened in any glTF viewer: Windows 3D Viewer, Blender, the online viewer at gltf.report, etc.

### Usage

```
eagle2gltf.exe board.brd
eagle2gltf.exe board.brd -o output.glb
eagle2gltf.exe board.brd -c path\to\glb_components\
eagle2gltf.exe board.brd -c path\to\glb_components\ -o board_with_parts.glb
```

### Arguments

| Argument | Description |
|---|---|
| `board.brd` | Path to the Eagle board file (required) |
| `-o`, `--output` | Output `.glb` path (default: next to the BRD file) |
| `-t`, `--thickness` | Board thickness in mm (default: read from BRD) |
| `-c`, `--components` | Folder with component GLB files |
| `--textures` | Folder with PNG textures (default: `<brd_stem>_textures/` next to BRD) |
| `--layer` | Board outline layer (default: `20`) |
| `--log` | Path to a log file |

### Textures

Textures (copper, solder mask, silkscreen layers) are generated by the Eagle ULP automatically into `<brd_stem>_textures/`.  
If you run `eagle2gltf.exe` manually without first exporting from Eagle, no textures will be available and the board will appear as a solid color.

### Temporary files

All intermediate files (textures, intermediate GLB) are stored in `NoABS_tmp/` next to the BRD. This folder can be safely deleted — it will be recreated on the next run.

## eagle2step — STEP board model generator

Generates a `.step` file for import into MCAD applications (Fusion 360, FreeCAD, SolidWorks, etc.).  
Uses OCCT via the bundled `drawexe_bundle`.

### Usage

```
eagle2step.exe board.brd
eagle2step.exe board.brd -o board.step
eagle2step.exe board.brd -c path\to\step_components\
eagle2step.exe board.brd -c path\to\step_components\ -a board_assembly.step
```

### Arguments

| Argument | Description |
|---|---|
| `board.brd` | Path to the Eagle board file (required) |
| `-o`, `--output` | Output `.step` path (default: next to the BRD file) |
| `-t`, `--thickness` | Board thickness in mm (default: read from BRD) |
| `-c`, `--step-dir` | Folder with component STEP files → produces an assembly |
| `-a`, `--assembly-output` | Output assembly STEP path (default: `<brd_stem>_assembly.step`) |
| `--layer` | Board outline layer (default: `20`) |
| `--debug` | Verbose OCCT log |

### Component STEP files

When `-c` is specified, the tool looks up STEP files by Eagle footprint name. File names must match footprint names (case-insensitive). Components with no matching file are skipped with a warning.

The result is two files: `board.step` (board only) and `board_assembly.step` (board + components).

## Troubleshooting

**Board has no textures (solid color)**  
Textures were not exported from Eagle. Run via the ULP, or point `--textures` to the texture folder manually.

**Components are not added**  
The GLB/STEP file name must exactly match the Eagle footprint name. For example, footprint `SOIC8` → file `SOIC8.glb`.

**eagle2step cannot find drawexe**  
The `drawexe_bundle/` folder must be located next to `tools/` (i.e. inside `release_artifacts/`). Do not move `eagle2step/` separately from the rest of the structure.
