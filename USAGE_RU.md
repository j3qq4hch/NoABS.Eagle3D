# NoABS Eagle3D — Инструкция по использованию

## Структура release_artifacts

```
release_artifacts/
  tools/
    export3D.ulp          ← ULP-скрипт Eagle (шаг 1)
    export3D_step2.ulp    ← ULP-скрипт Eagle (шаг 2, запускается автоматически)
    eagle2gltf/           ← генератор GLB-модели платы
    eagle2step/           ← генератор STEP-модели платы
  glue/                   ← GUI-оболочка (запускается напрямую)
  drawexe_bundle/         ← OCCT-движок (используется eagle2step)
```

---

## ULP-скрипты (экспорт из Eagle)

ULP автоматизирует весь процесс экспорта 3D-модели прямо из Eagle.

### Быстрый старт

1. Открыть плату в Eagle Board Editor
2. **File → Execute Script** → выбрать `export3D.ulp`
3. При первом запуске появится диалог настроек:
   - **DPI** — разрешение текстур (400 — хороший баланс, 600+ — для детальных плат)
   - **Tools dir** — папка `tools/` из `release_artifacts` (где лежат `.exe`)
   - **GLB dir** — папка с GLB-файлами компонентов (можно оставить пустой — будет плата без компонентов)
4. Нажать OK. Eagle экспортирует текстурные слои, затем автоматически запустит `export3D_step2.ulp`, который вызовет `eagle2gltf.exe`
5. Готовый `.glb` файл появится рядом с `.brd` файлом

**При следующих запусках диалог не появляется** — настройки сохраняются в `NoABS_tmp/export3d_settings.ini` рядом с BRD.  
Чтобы изменить настройки — удалить этот файл и запустить ULP заново.

### GLB-файлы компонентов

Библиотека 3D-моделей компонентов в формате GLB берётся из отдельного репозитория.  
Папку с GLB указывать в поле **GLB dir**. Имена файлов должны совпадать с именами футпринтов Eagle (регистр не важен).

## Метаданные позиционирования компонентов

Чтобы 3D-модель компонента правильно встала на плату (нужная высота, поворот, смещение относительно точки привязки футпринта), в описании футпринта должны быть метаданные в формате `<!--3d:{...}-->`.

Эти метаданные содержат параметры трансформации: смещение по осям X/Y/Z и углы поворота. Без них компонент будет размещён в нулевой точке футпринта без каких-либо поправок, что для большинства корпусов даст неправильное положение.

Метаданные прописываются в библиотеке Eagle при помощи **glue** — GUI-утилиты из этого же пакета. Glue позволяет визуально подобрать параметры размещения 3D-модели и сохранить их в описание футпринта.

## eagle2gltf — генератор GLB модели платы

Генерирует `.glb` файл с 3D-моделью платы и (опционально) компонентами.  
GLB открывается в любом glTF-просмотщике: Windows 3D Viewer, Blender, онлайн-просмотщик gltf.report и др.

### Использование

```
eagle2gltf.exe board.brd
eagle2gltf.exe board.brd -o output.glb
eagle2gltf.exe board.brd -c path\to\glb_components\
eagle2gltf.exe board.brd -c path\to\glb_components\ -o board_with_parts.glb
```

### Аргументы

| Аргумент | Описание |
|---|---|
| `board.brd` | Путь к файлу платы Eagle (обязательный) |
| `-o`, `--output` | Путь к выходному `.glb` (по умолчанию: рядом с BRD) |
| `-t`, `--thickness` | Толщина платы в мм (по умолчанию: берётся из BRD) |
| `-c`, `--components` | Папка с GLB-файлами компонентов |
| `--textures` | Папка с PNG-текстурами (по умолчанию: `<brd_stem>_textures/` рядом с BRD) |
| `--layer` | Слой контура платы (по умолчанию: `20`) |
| `--log` | Путь к файлу лога |

### Текстуры

Текстуры (слои медь, маска, шелкография) генерируются Eagle ULP автоматически в папку `<brd_stem>_textures/`.  
Если запускать `eagle2gltf.exe` вручную без предварительного экспорта из Eagle — текстур не будет, плата будет однотонной.

### Промежуточные файлы

Все временные файлы (текстуры, промежуточный GLB) сохраняются в `NoABS_tmp/` рядом с BRD. Эту папку можно удалять — она будет пересоздана при следующем запуске.

## eagle2step — генератор STEP модели платы

Генерирует `.step` файл платы для импорта в MCAD-системы (Fusion 360, FreeCAD, SolidWorks и др.).  
Использует OCCT через встроенный `drawexe_bundle`.

### Использование

```
eagle2step.exe board.brd
eagle2step.exe board.brd -o board.step
eagle2step.exe board.brd -c path\to\step_components\
eagle2step.exe board.brd -c path\to\step_components\ -a board_assembly.step
```

### Аргументы

| Аргумент | Описание |
|---|---|
| `board.brd` | Путь к файлу платы Eagle (обязательный) |
| `-o`, `--output` | Путь к выходному `.step` (по умолчанию: рядом с BRD) |
| `-t`, `--thickness` | Толщина платы в мм (по умолчанию: берётся из BRD) |
| `-c`, `--step-dir` | Папка с STEP-файлами компонентов → создаёт сборку |
| `-a`, `--assembly-output` | Путь к выходному STEP сборки (по умолчанию: `<brd_stem>_assembly.step`) |
| `--layer` | Слой контура платы (по умолчанию: `20`) |
| `--debug` | Подробный лог OCCT |

### STEP-файлы компонентов

При указании `-c` скрипт ищет STEP-файлы по имени футпринта Eagle. Имена файлов должны совпадать с именами футпринтов (регистр не важен). Компоненты без совпадающего файла пропускаются с предупреждением.

Результат: два файла — `board.step` (только плата) и `board_assembly.step` (плата + компоненты).

## Типичные проблемы

**Плата без текстур (однотонная)**  
Текстуры не были экспортированы из Eagle. Запустите через ULP или укажите `--textures` вручную.

**Компоненты не добавляются**  
Имя GLB/STEP-файла должно точно совпадать с именем футпринта Eagle. Например, футпринт `SOIC8` → файл `SOIC8.glb`.

**eagle2step не находит drawexe**  
Папка `drawexe_bundle/` должна лежать рядом с папкой `tools/` (т.е. в `release_artifacts/`). Не перемещайте `eagle2step/` отдельно от остальной структуры.
